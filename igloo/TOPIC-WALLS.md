# Looking back: figures on the right, imagery on the left

Open `index.html` at the repository root, or `igloo/9.html`. Both use the latest default-branch live 3D show. `igloo/index.html` remains the older footage-based show.

The latest source is `Ireland_2036_Looking_Back(1).pdf` (19 pages). Image provenance and the PDF checksum are recorded in `assets/topics/sources.json`. The supplied JSON is the default venue calibration. `assets/looking-back-preset.json` is its reusable preset with the corrected running order. Settings use a new local-storage namespace so older calibration and the old ten-caption script cannot silently override this edition.

## Wall composition

- Wall 2 / Right: live text rebuilt from the PDF, white and gold over a dark translucent mat. Three large numbers, their labels, and the PDF's supporting actions. Education includes the three supporting actions and figures from the latest PDF's page 15. All figures retain the source's illustrative-prototype label.
- Wall 4 / Left: embedded PDF images, extracted at their source resolution, on a transparent canvas. Images use contain sizing, retain their proportions and stay inside a smaller panel. No white slide background is projected.
- Front and back keep the landscape. Opening and closing story captions still appear. Repeated topic captions are off by default (`capOn: 0`).
- Neither panel renders on the floor. The floor map calibration is retained. The panels clear before the map-fold outro; the feature wall is the supplied front wall (`owall: 0`).
- Sustainability uses the garden image newly supplied on page 12. Every topic now has matching PDF information and imagery.

The same physical-wall shader works for 360, walls + floor, and desk preview, including non-square rooms. Panels have bounded dimensions and respect corners and the floor join. The per-wall enable switches control the topic cards, not the landscape.

## Operator controls

`C` → **Topic walls**: enable right/left, show imagery, repeat captions, horizontal/vertical flip, panel size/height, glass opacity, text sizes, image size/height/opacity/edge softness. JSON copy/paste includes all settings. `panFlipY: 1` handles the atlas's top-down canvas orientation and produces upright content; turn it off only if the venue needs inverted content.

The supplied extra keys (`nv*`, `lwRadius`, `lwShadow`, `lwSpread`, `lwVignette`, `lwTint`, `lwGround`, `film`, `mapb`, `mapd`, `harp`, `arp`, `sea`, `wFront`, `wBack`) are preserved on export for compatibility. The current repository did not implement them; this change does not invent their missing native-voice/effect behavior. Active floor/world calibration uses the existing `fmapb`, `lines`, `grade`, `warm`, `nlight`, `land`, `inset`, `fscale`, `tiltx`, `tilty`, `dscale`, `dx`, `dy` controls. Front/back carry no topic cards.

## Rendering and checks

The figures remain canvas text rendered into a mipmapped GPU texture. Only the current and previous topic textures are cached, and nothing is repainted per frame. Source imagery is at the PDF's original resolution, not claimed as native 4K. The existing adaptive world renderer is unchanged; 60 fps requires measurement on the venue GPU.

Run `node --test tests/topic-walls.test.cjs`. Browser projection checks are described in `tests/topic-walls.browser.cjs` and use fixture data only in the test route, never in the shipped show. The live map still requires the original external terrain and satellite services.

Verified in headless Chromium with software WebGL: both entry points, all eight topics, all three output modes, shader compilation, image loading and JSON import. The generated card atlases and projected walls were visually inspected. This isolates the projection from external terrain services; it is not a claim of venue GPU performance or a live-map network test.
